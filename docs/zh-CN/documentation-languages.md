# 双语文档维护规则

[English](../documentation-languages.md) | 简体中文 · [中文目录](README.md)

本规则适用于英文 `README.md`、简体中文 `README_CN.md` 和已翻译的入口指南，规定文档维护方式，不改变产品行为或资产等级含义。

## 配对入口

保留英文默认首页，顶部提供双向语言链接。两版的章节顺序、能力声明、前提、命令、示例、版本和限制应对应。正文自然翻译，API 名称、键、标识符、文件名和可执行代码保持原样。中文跨组件导航优先使用各组件中文首页；未翻译的目标明确标注“英文”。

中文指南放在 `docs/zh-CN/`，每页链接对应英文来源与中文目录。目录明确区分已有中文翻译和仅英文参考。精确行为由 API、schema、已接受契约和经核验实现决定，翻译不能创建第二套产品规格。

## 同步更新与审阅

修改能力、版本、命令或限制时，在同一变更中更新配对页面，同时比较语义和语法。尤其保持显式 v2 L1/L2/L3 内容语义、`assetAssessment` 与 `reconstructionVerification` 的分离，以及 `L3 / NOT_REQUESTED` 的有效性；不得将内容授级翻译成已验证软件功能等价。

逐项审阅两版的安装前提、预期结果、恢复路线、源码/发行包区别及能力限定。示例应等义，配对 README 的命令/代码块必须完全一致；中文安装指南也复用英文命令块。

运行已有文档检查：

```sh
node scripts/check-documentation.mjs
git diff --check
```

双语守卫检查双向链接、版本、发行文件名、代码/技术标识一致性，以及双语入口中的本地链接和锚点。它不能证明正文语义等价，仍需语义审阅。总项目另检查中文安装命令及 v2 行为方面/闭合类别覆盖。

## 发行包

后续从源码构建的组件包和总发行包应包含两种 README 与已有中文指南，并在候选包中核对存在性和离线链接。源码文档可在发行后继续完善；不得为增加翻译替换已发布 tag、归档、已安装程序或资产快照。源码文档变更不等于新软件发布或日常环境切换决定。
