# EvoPilot Harness v1.1.1 Release Notes

EvoPilot Harness v1.1.1 upgrades the public README and technical documentation set while keeping the runtime CLI, Harness Hub, and published Catalog contract compatible with EvoPilot `>=3.0.0`.

## What Changed

- Reworked the root README into a concise product entry with quick start, architecture overview, capability routing, development commands, and documentation links.
- Added a complete `docs/` tree for new users, AI agents, Harness administrators, EvoPilot integrators, Dashboard integrators, production operators, and schema reviewers.
- Added `docs/cli/AGENTS.md` as the shortest safe path for WorkBuddy, Codex, Claude Code, CI jobs, and other command-line agents.
- Added CLI quickstart, command reference, automation rules, and workflow guides.
- Added architecture, Catalog boundary, Harness template contract, source-to-Harness, Harness evolution, Harness Hub integration, EvoPilot integration, operations, troubleshooting, and reference contract documents.
- Added `npm run docs:links` and included it in `npm run check` so local Markdown documentation links are validated.

## Boundary

`evopilot-harness` remains independently runnable and continues to own Harness management, evolution, approval, versioning, publication, and the Harness Hub UI. EvoPilot consumes the published Catalog directory dynamically; Dashboard may embed the Hub but does not own Harness state.

## Run

```bash
npm ci
npm run check
npm run hub:serve
```

Open `http://127.0.0.1:4176`.

Container:

```bash
docker run --rm -p 4176:4176 ghcr.io/yeliang-wang/evopilot-harness:1.1.1
```

## Validation

- `npm run check`
- `git diff --check`
- `node src/index.mjs --help`
- Harness Hub `/api/hub/snapshot` smoke on a local port
