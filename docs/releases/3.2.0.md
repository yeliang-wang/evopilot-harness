# EvoPilot Harness 3.2.0

v3.2.0 turns Proposal review from draft inspection into a formal, evidence-bound product capability. The Guided Operator now automatically runs and presents every Review Report before asking for a human decision.

## Highlights

- Added the Proposal Review Engine with deterministic gates, independent GLM semantic review, structured synthesis, and a formal `evopilot-harness-proposal-review/v1` Schema.
- Added five explicit verdicts: `READY_FOR_HUMAN_APPROVAL`, `REVISE`, `SPLIT`, `REJECT`, and `NEED_MORE_EVIDENCE`.
- Review Reports include findings, reasons, evidence citations, corpus coherence, every source membership, product boundary, Catalog overlap, definition quality, evaluation sufficiency, actions, blockers, model/token usage, algorithm version, and digests.
- Added `proposal inspect` for raw Proposal reading and `proposal review-inspect` for persisted Review Report reading, so inspection and review are no longer conflated.
- `proposal approve` now requires a current, valid, `READY_FOR_HUMAN_APPROVAL` Review Report plus separate human approval and evaluation review.
- The Guided Operator automatically reviews all Proposals returned by a confirmed production stage, presents every structured report, and stops without approving or publishing.
- Harness Hub snapshots expose Review status, verdict, report digest, and review-driven next actions.

## Authority And Compatibility

The original Advisor and the independent Proposal semantic reviewer are separate evidence-bound calls. Neither may execute source projects, approve, publish, mutate configuration, invent evidence, or override deterministic gates. Asset v3, Catalog, Registry, published Harness assets, and the v2 compatibility surface remain unchanged. Existing v3 approval automation must add the formal review step.

No external test corpus, local project, generated Proposal, or Review Report is added to the built-in Harness asset library.
