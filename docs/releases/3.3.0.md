# EvoPilot Harness 3.3.0

v3.3.0 establishes governed production-feedback evidence without moving project execution into `evopilot-harness`.

## Shipped

- `HarnessExecutionFeedbackPackage v1` with approval, redaction, expiry, provenance, payload integrity, and immutable Bundle/Profile/Component closure.
- Static `feedback inspect`, `validate`, `ingest`, `aggregate`, `report`, and `process` commands with JSON output and deterministic `--now` injection.
- Content-addressed idempotency, package-id conflict detection, persisted rejection reasons, and no duplicate effect counting.
- `HarnessEffectivenessReport v1` grouped by Bundle, Profile, Component, and version, including Outcome, Process, Safety, Cost, sample count, source diversity, context, missing fields, and uncertainty.
- `EvaluationPack v2` for four-dimensional effect criteria while retaining v1 compatibility.
- Read-only Harness Hub feedback counts, rejection reasons, reports, and latest four-dimensional effect projection.
- Roadmap intent and Release gates in local workflows and GitHub Actions.

## Authority Boundary

Feedback remains an Evidence Source. v3.3.0 does not create a Harness Delta Proposal, approve or publish an asset, execute a Goal Loop, run source-project commands, or train a model. Feedback packages and effectiveness reports never enter a Harness Catalog.

`--production-log` is still available as redacted unstructured Proposal evidence. It is not equivalent to the structured feedback package.

## Production Claim

Independent contract fixtures verify the `evopilot-harness` consumer path. A complete cross-project production loop additionally requires a compatible control plane to export real approved `HarnessExecutionFeedbackPackage` artifacts; this Release does not claim that external producer is already shipped.
