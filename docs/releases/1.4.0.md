# EvoPilot Harness 1.4.0

Release date: 2026-08-10

## Summary

`evopilot-harness` 1.4.0 adds source-root Corpus Lifecycle support. Operators can now point the CLI at a directory that contains many historical projects, let the CLI scan valid project roots, auto-match each project, group by target Harness, dedupe nested modules, generate one reviewable draft per group, approve the corpus plan, and publish the resulting Harness packs.

Single-project `detect`, `detect batch`, `evolve`, atomic `evolution` commands, Catalog, Registry, and Harness Hub behavior remain compatible.

## Added

- `corpus scan --source-root <path>`
- `corpus plan --source-root <path>`
- `corpus list`
- `corpus review <corpus-id>`
- `corpus approve <corpus-id>`
- `corpus publish <corpus-id>`
- `evolve corpus --source-root <path>`
- Corpus run storage under `.evopilot-harness/corpora/<corpus-id>/`
- Per-group draft packs under `.evopilot-harness/corpora/<corpus-id>/drafts/<target-harness-id>/`
- Corpus run summaries in Harness Hub snapshots

## Operator Flow

```bash
node src/index.mjs corpus scan \
  --source-root /path/to/project-root \
  --include-modules \
  --json

node src/index.mjs corpus plan \
  --source-root /path/to/project-root \
  --include-modules \
  --max-projects-per-group 5 \
  --json

node src/index.mjs corpus approve <corpus-id> \
  --confirmed-by <administrator> \
  --confirmation "Reviewed corpus grouping, dedupe decisions, generated drafts, validation, and publication impact." \
  --json

node src/index.mjs corpus publish <corpus-id> --json
```

`evolve corpus` is a one-command wrapper around `corpus plan`. It stops at `REVIEW_REQUIRED` by default and only publishes with explicit `--approve-and-publish`, `--confirmed-by`, and `--confirmation`.
