# evopilot-harness v4.2.2

> Status: candidate

v4.2.2 repairs installed Agent-host LLM configuration. A fresh external Workspace now points to its own manually maintained `models.json` and receives only a safe `models.example.json` template. Existing v4.2.1 Workspaces migrate only when their missing model path exactly matches the old package-local default; custom paths and user files are preserved.

Advisor, Proposal Review, `llm v3-models`, and `llm v3-doctor` now resolve configuration in one order: explicit command input, `EVOPILOT_HARNESS_LLM_MODELS_FILE`, then the external Workspace configuration. Workspace and MCP status expose the resolved non-secret path, template availability, configuration presence, migration result, and next action.

The npm artifact still excludes `models.json` and credentials. The Engine, Digital Expert, and Agent host cannot create or change an API key, approve a Proposal, or publish an Asset. This patch ships through GitHub Release, npm, and local stdio MCP only; GHCR and deployment are excluded.
