# EvoPilot Harness 3.1.0

v3.1.0 makes required Advisor behavior observable and consistent across every supported Evidence Source. It does not add project-specific domains or matching rules.

## Highlights

- `llm v3-models` now states that it verifies configuration only.
- `llm v3-doctor` performs a minimal live GLM JSON-contract request with a 60-second default and returns redacted connectivity evidence.
- Full production Advisor calls use a separate 180-second default while retaining an explicit CLI override, avoiding false transport failures for evidence-bound reasoning without weakening stop gates.
- Advisor Policy can permit one audited structure/citation repair after invalid JSON or contract rejection; all attempts, validations, timing, and aggregate token usage remain in the Advisor Run.
- Large Evidence Graphs use a deterministic, Policy-budgeted Advisor projection with reasoning-first and source/kind coverage; the complete Graph remains intact and projection evidence is reported.
- Every Advisor attempt is persisted under the external Workspace, including failures and policy skips.
- Local projects, Source Roots, Git repositories, attachments, logs, historical Harnesses, notes, and mixed evidence share one Advisor Run Contract.
- Source Root responses expose aggregate and per-group Advisor status, usage, validation, timing, failure type, reason, and result path.
- A failed required Advisor returns `BLOCKED` with a non-zero exit code while preserving Evidence Graph and Proposal artifacts for diagnosis.
- The guided Operator Skill can enter a separately authorized read-only diagnostic state without gaining edit, Git, release, credential, or Source execution authority.

## Compatibility

The v3 asset API, Catalog, Registry, published Harness assets, and v2 compatibility surface remain unchanged. The stricter exit status applies only when an Advisor is required but does not succeed; successful review-stage workflows remain compatible.

## Product Boundary

This release improves platform-level observability and control flow. Source material remains evidence only. No user project, directory layout, detected domain, or generated Proposal is added to the built-in Harness asset library.

## Validation

The release candidate is validated through Skill Guard tests, single-source and multi-source Advisor tests, Source Root success/failure aggregation tests, the complete project test suite, v3 validation, documentation links, architecture checks, and release artifact verification.
