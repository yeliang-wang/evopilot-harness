# EvoPilot Harness v1.1.0 Release Notes

EvoPilot Harness v1.1.0 adds the independent Harness Hub / expert marketplace UI while keeping the CLI and published Catalog contract compatible with EvoPilot `>=3.0.0`.

## What Changed

- Added `evopilot-harness hub serve` for a standalone browser UI owned by `evopilot-harness`.
- Added `evopilot-harness hub snapshot` for AI Agent-readable Hub state, including Catalog entries, Harness contracts, lifecycle commands, source types, and local evolution runs.
- Added static Hub assets under `ui/harness-hub/`; the UI reads `/api/hub/snapshot` when served and can use a generated snapshot for offline release review.
- Added Docker, Compose, CI, release-artifact generation, release-artifact verification, SBOM, provenance, checksum, and GHCR image metadata support.
- Preserved atomic CLI commands and the one-command `evopilot-harness evolve` lifecycle.

## Boundary

`evopilot-harness` is independently runnable. It owns Harness management, evolution, approval, versioning, publication, and its own UI. EvoPilot can consume the published Catalog directory, and `evopilot-dashboard` may embed this Hub in an iframe, but neither integration is required for `evopilot-harness` to run end to end.

## Run

```bash
npm ci
npm run check
npm run hub:serve
```

Open `http://127.0.0.1:4176`.

Container:

```bash
docker run --rm -p 4176:4176 ghcr.io/yeliang-wang/evopilot-harness:1.1.0
```

## Validation

- `npm run check`
