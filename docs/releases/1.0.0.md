# evopilot-harness v1.0.0 Release Notes

`evopilot-harness v1.0.0` is the first stable release of the independent Harness lifecycle and publication project for EvoPilot `v3.0.0` and later.

## What Changed

- `evopilot-harness` now owns Harness lifecycle management, source collection, auto-match, draft generation, review, approval, versioning, and Catalog publication.
- EvoPilot consumes Harnesses by dynamically reading configured Catalog directories and `CATALOG.md`; it no longer imports, mounts, publishes, or evolves Harness definitions.
- The CLI keeps atomic lifecycle commands and adds one-command `evopilot-harness evolve` for source-project, attachment, note, and production-log driven Harness evolution.
- Published Catalogs now declare `compatibleEvopilot: ">=3.0.0"`.
- JSON output is stable for AI Agent automation, including approval and publish flows.

## Compatibility

- Compatible EvoPilot: `>=3.0.0`.
- Catalog schema: `evopilot-harness-catalog`.
- Harness schema: `evopilot-harness-template/v1`.
- Node.js: 22 or later.

## EvoPilot Consumption

Point EvoPilot at the published Catalog directory:

```bash
EVOPILOT_HARNESS_CATALOG_DIRS=/path/to/evopilot-harness/published
```

EvoPilot reads the directory dynamically when listing Catalogs or generating a goal plan. The selected Harness is recorded on the plan as `selectedHarness` with Catalog id, path, version, and digests.

## Validation

```bash
npm test
npm run catalog:publish
npm run catalog:validate
```
