# EvoPilot Harness 3.4.0

> Status: local release candidate. Commit, push, tag, GitHub Release, package/image publication, and deployment are not authorized by the implementation approval.

v3.4.0 makes every proposed Harness asset evolution an evidence-linked, reviewable Delta with portable Evaluation coverage and deterministic impact closure before human approval or immutable publication.

## Highlights

- `AssetDeltaProposal v1` covers Component, Profile, Bundle, Ontology, Matcher Policy, Advisor Policy, and Evaluation assets.
- Exact before/after documents, versions, digests, change paths, and Evidence Graph ids make the proposed state transition inspectable.
- `EvaluationPack v3` carries portable positive and negative cases, context, assertions, validator/scorer versions, baselines, expected outcomes, and regression boundaries.
- Five Proposal decisions distinguish evolution, composition, new Profile creation, no change, and insufficient discriminating evidence.
- Deterministic compatibility, dependency, blast-radius, expected-effect, regression, and rollback analysis blocks incomplete Proposals.
- Closure validates embedded asset schemas, binds proposed assets and immutable Catalog baselines, and recomputes all change and impact fields.
- Approval binds the current Review Report and approved content by digest; all mutating decisions require reviewed Evaluation cases.
- Publication rebuilds Delta after-states from the exact published assets and Evaluation so persisted digests match the immutable files.
- `proposal validate` exposes Delta/Evaluation closure through scriptable JSON before independent semantic review.
- Harness Hub shows decision, Delta, impact, Evaluation coverage, blockers, and next action.

## Decision Boundary

`EVOLVE_EXISTING`, `COMPOSE_NEW_BUNDLE`, and `PROPOSE_NEW_PROFILE` may advance only after deterministic validation, independent Proposal Review, approved positive/negative Evaluation cases, and explicit human approval. Review-report or approved-content digest drift blocks publication. `NO_CHANGE` and `NEED_MORE_EVIDENCE` are auditable terminal decisions with `publicationAllowed=false`.

GLM can explain and recommend but cannot replace the deterministic decision, invent evidence, pass Delta/Evaluation closure, approve, or publish.

## Compatibility

- EvaluationPack v1 and v2 remain readable and validated.
- Existing v2 CLI, Asset, Catalog, and Registry automation remains available as a compatibility layer.
- Engine, Harness asset, Ontology, Policy, Evaluation, and Catalog versions remain independent.
- Existing immutable published asset versions are not rewritten.
