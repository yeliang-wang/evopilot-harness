# EvoPilot Harness v1.3.0 Release Notes

EvoPilot Harness v1.3.0 adds Harness Detect Algorithm v1 and Template Quality Standard v1. The release makes source-driven Harness evolution more explicit: operators can detect a source project's role, candidate Harness, parent references, and ambiguity before generating or publishing a draft.

## Added

- `detect` CLI command for single source projects, attachments, logs, notes, and goals.
- `detect batch` CLI command for scanning many candidate project roots without publishing anything.
- Source Profile output with languages, build tools, frameworks, dependencies, imports, symbols, architecture signals, source roles, negative signals, recommended Harness, and sensitive material findings.
- Template Quality Standard v1 and `--strict` validation for `productBoundary`, `matchPolicy`, `executionModel`, `evidenceContract`, `qualityGate`, and domain execution.
- External sample validation script for local historical corpora: `scripts/validate-howbuy-samples.mjs`.

## Changed

- `evolve` now reuses the deterministic detect result before generating a draft.
- Source Harness templates now carry richer product boundaries, match policies, execution models, evidence contracts, and quality gates.
- The default deterministic match threshold is `0.45`.
- Narrow source roles can now produce `CREATE_NEW_WITH_PARENT_REFERENCE`, so a Redis client library can create a Redis client Harness while referencing a broader distributed cache Harness as parent context.
- Ambiguous candidates return `REVIEW_REQUIRED` for administrator selection.

## Validation

Release validation must include:

```bash
node --check src/index.mjs
npm test
npm run check
node scripts/validate-howbuy-samples.mjs --source-root <external-read-only-project-root> --source harnesses
git diff --check
npm run release:artifact
npm run verify:release-artifact
```

The external Howbuy path is validation input only. It is not copied into `harnesses/` and is not published as fixed template content.
