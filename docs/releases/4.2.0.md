# EvoPilot Harness 4.2.0

> Status: candidate; implementation and Target acceptance are evaluated locally. No Git tag, GitHub Release, npm publication, GHCR publication, or deployment is authorized or claimed.

v4.2.0 adds governed professional Asset learning while preserving the existing Proposal, Review, approval, and publication lifecycle as the only route to Catalog assets.

## Candidate scope

- Declarative `ResearchAdapterManifest` and static reviewed `ResearchEvidencePackage` import without Engine network or code execution.
- Append-only `AssetCurriculumEntry`, immutable `AssetCurriculumSnapshot`, and reproducible `EvidenceRunManifest` bindings.
- Policy-versioned vector `ProfessionalCompletenessReport` with missing/error accounting and append-only rescoring.
- Evidence-only `ContributionEvidencePackage` and `DomainRoleProposal`, including positive/negative, overlap, ambiguity, and false-classification analysis.
- Atomic CLI, local stdio MCP, persistent Agent Session, generated Digital Expert adapters, WorkBuddy capability discovery, read-only Harness Hub projection, and installed-package operation.
- Additive compatibility for v3 and v4.1 Workspaces, assets, Proposals, comparison/calibration evidence, Catalogs, Registries, and Sessions.

## Authority and security

Research and community contributions are supplemental evidence only. They cannot approve, publish, activate policy, execute a source project, fetch a URL, execute an adapter/plugin, mutate a Catalog, or authorize an Engine Release. Optional integrity attestations never replace provenance, license, review, lifecycle, or human gates.

See [Professional Asset Learning](../guides/professional-asset-learning.md). Release requires a separate explicit user decision after candidate acceptance and the exact Roadmap Release Gate.
