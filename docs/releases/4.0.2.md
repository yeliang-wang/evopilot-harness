# EvoPilot Harness 4.0.2

v4.0.2 closes the installed Agent distribution path. It packages the Engine, Digital Expert, Adapters, local stdio MCP server, schemas, required built-in assets, and Harness Hub runtime as `@evopilot/harness`, while keeping user state and release authority outside the package.

## Added

- Exact package identity `@evopilot/harness@4.0.2` with the `evopilot-harness` binary and a curated `files` allowlist.
- `evopilot-harness agent bootstrap --host <id> --workspace <path> --json` for the packaged Adapter path, compatibility binding, exact version-pinned MCP command, and external Workspace contract.
- OIDC Trusted Publishing workflow with provenance, explicit dist-tags, Registry integrity, signature, SLSA attestation, and clean exact-version install verification.
- A separate, one-time first-publication Bootstrap that is manually confirmed, token-isolated, package-existence-aware, and permanently superseded by OIDC Trusted Publishing after the package exists.
- Local release tarball as a GitHub Release artifact alongside source, SBOM, provenance, and checksums.
- The actual WorkBuddy currently installed on the acceptance Mac (`2.106.4` for the recorded run) passes pre-release acceptance from an isolated local tarball, with no source checkout resolution and no Workspace mutation during `inspect_capabilities`.

## Compatibility

- Supports MCP `2025-11-25`, `2025-06-18`, `2025-03-26`, and `2024-11-05` over local stdio.
- Standard MCP clients may initialize without a non-standard compatibility extension. A supplied incompatible extension still fails before mutation, and the Digital Expert must compare the post-initialize capability result with its manifest lock.
- The v3 JSON CLI and v3 Engine lifecycle remain compatible.

## Distribution Boundary

The npm package excludes user Organization Catalogs, published Workspace state, Sessions, source projects, logs, attachments, `models.json`, credentials, private keys, tests, governance files, and release evidence. Public npm availability is proven only after the Registry returns the exact package metadata, integrity, signatures, provenance, and expected dist-tag.

GitHub Release, npm publication, optional GHCR publication, and remote deployment are separate actions. This release note does not authorize or prove any of them by itself.

npm account, scope ownership, 2FA, temporary Bootstrap token, GitHub Environment, and Trusted Publisher configuration are external Release Review inputs and are not stored or created by this release.

## Acceptance

- Curated package verification and secret/path policy.
- Clean temporary tarball installation, CLI, bootstrap, stdio MCP, Digital Expert resource, tool list, and shutdown smoke.
- Real WorkBuddy startup and one read-only Engine capability call from the installed tarball.
- Full Roadmap, architecture, Digital Expert, v3 lifecycle, test, release-artifact, documentation-link, and diff checks required before release review.
