# v4.1.0 Acceptance

This page defines the acceptance surface for the v4.1.0 controlled comparative-evidence candidate. A passing implementation suite does not authorize commit, push, tag, GitHub Release, npm, GHCR, or deployment.

## Deterministic Commands

```bash
npm run roadmap:check
npm run digital-expert:check
node scripts/validate-digital-expert-scenario-coverage.mjs
node --test tests/v4.1.test.mjs
npm run verify:architecture
npm test
npm run v3:check
npm run check
npm run package:verify
npm run package:smoke
git diff --check
```

Release-version alignment is checked only during the separate Release Review:

```bash
npm run roadmap:release -- 4.1.0 --json
```

## Acceptance Matrix

| Criterion | Required evidence |
|---|---|
| Package and report integrity | Schema, package/payload/report digests, approval, redaction, expiry, provenance, immutable asset and Proposal binding, tamper negatives |
| Fail-closed comparability | Task, source snapshot, environment, model, toolchain, EvaluationPack, scorer set, metrics, and asset-binding mismatches produce separate strata and no mixed aggregate |
| Immutable history | Idempotent duplicate ingestion, package-id conflict rejection, immutable reports, append-only rescore record, raw and prior mutation flags false |
| Deterministic result | Paired samples, wins/losses/ties, missing observations, uncertainty, conflicts, safety blockers, limitations, and exactly one bounded recommendation |
| Proposal closure | Expected effect versus comparatively supported effect, current report snapshot, new-evidence/tamper/digest-drift approval and publication blockers |
| Calibration | Independently reviewed cases, Baseline/Candidate matching and Proposal policy replay, ranking, abstention, false-upgrade, false-new-profile, regressions, conflicts, uncertainty, active-policy non-mutation |
| Agent path | Comparison and calibration Plans, explicit Plan confirmation, `EVIDENCE_REVIEW_REQUIRED`, exact report presentation and acknowledgement, interruption/cross-Adapter resume, no human CLI requirement |
| Installed package | Clean exact tarball install, installed binary/modules, real stdio MCP Comparison and Calibration Sessions, report acknowledgement, no source checkout |
| Hub and docs | Read-only status, recommendation, uncertainty, blockers, provenance, limitations, next action, secret/path scan, link validation |
| Boundary and compatibility | 28 Engine module anchors, 7 Agent enforcement anchors, no source execution/Catalog mutation/LLM authority/policy activation, existing v3/v4 behavior retained |

## Required Scenario Outcomes

- Candidate improvement reaches `CANDIDATE_READY_FOR_HUMAN_REVIEW` but does not approve or publish.
- A safety regression reaches `REVISE_CANDIDATE`; a published Candidate reaches non-executing `ROLLBACK_RECOMMENDED`.
- Every governed context mismatch reaches `NON_COMPARABLE`, exposes context strata, and reports `metrics=[]`.
- Insufficient pairs reach `NEED_MORE_EVIDENCE` without claiming Candidate superiority.
- Tampered, stale, unapproved, unredacted, or binding-drifted packages are rejected.
- Duplicate ingestion is idempotent; conflicting content under one package id is rejected.
- Rescoring preserves accepted packages and every prior report.
- A changed Proposal digest with older comparison evidence is `STALE` and blocking rather than being treated as absent evidence.
- Proposal calibration replays only the package digests in the reviewed Comparison Report; later packages require a new case-set version.
- Repeating calibration with the same case set and policy bindings returns the same report id, digest, and bytes without mutation.
- A semantic reviewer cannot override deterministic safety, comparability, uncertainty, conflict, or digest gates.
- Matching and Proposal calibration never mutates active policy.
- Proposal approval and publication stop after comparison evidence or report drift.
- Agent restart and cross-Adapter resume retain Session and exact report bindings.
- Installed-package operation resolves entirely below `node_modules/@evopilot/harness` and writes only the external Workspace.
- Hub snapshots contain `workspace:///...` and `package:///...` references instead of host absolute paths and reject every non-GET request.

## Authority Interpretation

Passing tests prove the implemented contracts and covered scenarios. They do not prove universal Harness quality, open-domain matching accuracy, causal improvement, production exporter availability, public npm publication, or every Agent host. Comparison and calibration remain evidence-producing review systems. Release remains a separate user-authorized action.
