# v4.1.2 Acceptance

This acceptance baseline proves the v4.1.2 documentation-system maintenance patch without treating documentation changes as evidence of new Engine behavior.

## Scope

- current Release and npm state synchronization across human and Agent-facing documentation;
- Guided Operator compatibility-link correction;
- expanded Markdown link coverage and release-state drift tests;
- package-version-derived npm verification and installed-runtime smoke assertions;
- unchanged v4.1 runtime, Harness assets, and product boundaries.

## Required Gates

```bash
npm run roadmap:check
npm run roadmap:release -- 4.1.2
npm run digital-expert:check
npm run verify:architecture
npm run check
npm run package:workbuddy
npm run release:artifact
npm run verify:release-artifact
git diff --check
```

## Acceptance Matrix

| Area | Required result |
|---|---|
| Documentation | Version-state tests pass and the native link audit reports zero errors and warnings across all configured roots. |
| Regression | The complete Node test suite and v3 compatibility acceptance pass without product-runtime changes. |
| Architecture | All Engine and Agent-operation boundary anchors remain enforced. |
| Package | The npm allowlist contains no forbidden paths, and a clean tarball installation passes CLI, bootstrap, stdio MCP, Comparison, and Calibration smoke. |
| Agent host | WorkBuddy and Generic host package bootstrap and conformance remain valid for the exact package version. |
| Release | The exact `4.1.2` Roadmap gate, release artifacts, SPDX SBOM, provenance, checksums, and diff checks pass. |

Passing this matrix proves the source and publication contract. GitHub Release and npm availability remain separate layers and must be verified independently after publication.
